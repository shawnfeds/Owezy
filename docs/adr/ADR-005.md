# ADR-005: Participant Privacy & Server-Side Authorization Boundary

## Status
Accepted

## Context
Privacy is a fundamental requirement. A participant accessing their split link must never be allowed to view financial details or item claims belonging to other participants (e.g. Alice must not see Bob's or Charlie's amount, items, or payment status).

## Decision
1. **Server-Side Enforcement**: Authorization and data scoping MUST be enforced strictly on the backend API server. Frontend filtering or UI hiding is strictly disallowed as a security mechanism.
2. **Participant Data Boundary**: The API endpoint servicing `participantToken` requests MUST return a specialized DTO containing ONLY:
   - Bill title/metadata (non-financial summary)
   - Items claimed by that specific participant
   - That participant's calculated share total
   - That participant's payment state
   - Splitter payment collection details (UPI ID)
3. **Information Leakage Prevention**: The full participant list, other participants' claimed items, and total bill financial breakdowns are stripped from participant responses at the server boundary.

## Consequences
- **Positive**: Strict data isolation, protection of participant privacy, prevention of IDOR (Insecure Direct Object Reference) vulnerabilities.
- **Negative**: Requires distinct DTOs and query handlers for Splitters vs Participants.
- **Mitigation**: Clear separation of `GetSplitterBillQuery` and `GetParticipantShareQuery` in `Owezy.Application`.
