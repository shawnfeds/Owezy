# ADR-007: OTP Abstraction & SMS Provider Strategy

## Status
Accepted

## Context
Splitter authentication relies on SMS OTP delivery. However, paid production SMS gateways should not be required for local development, integration testing, or automated CI/CD runs. Furthermore, committing to a specific production SMS vendor prior to vendor evaluation is premature.

## Decision
1. **Interface Isolation**: Define `IOtpService` and `ISmsProvider` abstractions in `Owezy.Application`.
2. **Development Provider (`DevelopmentSmsProvider`)**:
   - Active in `Development` and `Test` environments.
   - Logs generated OTP codes to application logs / console and records OTP in memory/database.
   - Allows fixed test OTP (e.g. `123456`) for automated integration tests.
3. **Production Provider (`ProductionSmsProvider`)**:
   - Vendor-agnostic abstraction configured via dependency injection in `Production` environment.
   - Concrete SMS vendor selection deferred until production deployment phase.
4. **Security Controls**:
   - OTP expiration (e.g. 5 minutes).
   - Maximum failed attempts limit (e.g. 3 attempts).
   - Resend cooldown (e.g. 60 seconds).
   - No plaintext OTP persistence (store SHA-256 hash of OTP).
   - Generic API responses to prevent account enumeration.

## Consequences
- **Positive**: Zero operational cost during local development and testing, vendor-agnostic SMS integration, strong rate and attempt safeguards.
- **Negative**: Requires environment-based DI configuration for `ISmsProvider`.
- **Mitigation**: Clean .NET `IServiceCollection` extension registration based on `IHostEnvironment`.
