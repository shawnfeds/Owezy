# ADR-009: UPI Payment Integration Boundary

## Status
Accepted

## Context
Owezy facilitates settlement between participants and splitters, but Owezy is NOT a payment gateway, payment aggregator, or financial intermediary. Handling financial transactions directly introduces massive compliance, security, PCI-DSS, and regulatory burdens.

## Decision
1. **Out of Scope**: No payment gateways, bank APIs, escrow accounts, auto-reconciliation, or transaction webhooks will be implemented in v1.
2. **UPI Link Generation**: The backend/client will generate standard UPI deep links:
   ```text
   upi://pay?pa={SplitterUpiId}&pn={SplitterName}&am={ParticipantAmount}&cu=INR&tn=Owezy+Bill+{BillTitle}
   ```
3. **Payment Status Flow**:
   - Participant clicks UPI link -> opens UPI app (Google Pay, PhonePe, Paytm, BHIM) -> completes transfer manually.
   - Participant clicks "Mark as Paid" in Owezy client -> updates participant payment status to `MarkedPaid`.
   - Splitter sees status update -> confirms receipt of funds -> marks status to `Confirmed`.

## Consequences
- **Positive**: Zero regulatory burden, zero payment processing fees, simple user experience.
- **Negative**: Relies on manual confirmation by Splitter rather than automated bank reconciliation.
- **Mitigation**: Perfectly matches lightweight v1 product goals.
